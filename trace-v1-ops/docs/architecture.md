# 睿码溯源系统 - 架构说明

## 一、系统架构概览

睿码溯源系统采用现代化的微服务架构，基于 Docker 容器化部署，确保系统的可扩展性和可靠性。系统由以下核心组件组成：

```
┌─────────────────────────────────────────────────────────────────┐
│                          客户端                                │
└───────────────┬─────────────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────────────┐
│                          Nginx                                 │
│                          (反向代理)                              │
└───────────────┬─────────────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────────────┐
│                        后端服务                                 │
│                      (FastAPI)                                  │
└───────────────┬─────────────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────────────┐
│                        数据库                                   │
│                     (PostgreSQL)                               │
└─────────────────────────────────────────────────────────────────┘
```

## 二、技术栈

### 1. 前端技术
- **框架**：Vue 3
- **UI 库**：Element Plus
- **路由**：Vue Router
- **状态管理**：Pinia
- **HTTP 客户端**：Axios
- **构建工具**：Vite

### 2. 后端技术
- **框架**：FastAPI
- **语言**：Python 3.9+
- **数据库**：PostgreSQL 14
- **ORM**：SQLAlchemy
- **二维码生成**：qrcode
- **文件处理**：pandas, zipfile
- **并发处理**：ThreadPoolExecutor

### 3. 容器化技术
- **容器平台**：Docker
- **编排工具**：Docker Compose
- **反向代理**：Nginx

## 三、核心组件

### 1. Nginx
- **作用**：作为反向代理，处理客户端请求，分发到后端服务
- **配置**：监听 80 端口，转发 API 请求到后端服务
- **静态文件**：提供前端静态文件服务

### 2. 后端服务
- **作用**：处理业务逻辑，提供 API 接口
- **API 模块**：
  - 二维码管理：生成、查询、导出
  - 批次管理：创建、查询、更新
  - 任务管理：创建、执行、查询
  - 扫码记录：查询、分析
  - 系统管理：配置、监控
- **任务系统**：基于内存队列的任务调度系统，处理批量生成和导出任务

### 3. 数据库
- **作用**：存储系统数据
- **表结构**：
  - `batch`：批次表，存储批次信息
  - `batch_task`：任务表，存储任务信息
  - `trace_code`：溯源码表，存储二维码信息
  - `scan_record`：扫码记录表，存储扫码信息

### 4. 存储
- **静态文件**：存储二维码图片、导出文件等
- **日志**：存储系统运行日志
- **备份**：存储数据库备份文件

## 四、数据流程

### 1. 二维码生成流程
```
客户端 → Nginx → 后端API → 创建任务 → 任务队列 → Worker执行 → 生成二维码 → 写入数据库 → 返回结果
```

### 2. 二维码导出流程
```
客户端 → Nginx → 后端API → 创建导出任务 → 任务队列 → Worker执行 → 生成Excel → 打包ZIP → 返回结果
```

### 3. 扫码溯源流程
```
客户端 → 扫码 → 后端API → 查询溯源码 → 记录扫码信息 → 返回溯源结果
```

### 4. 批次管理流程
```
客户端 → Nginx → 后端API → 创建批次 → 生成二维码 → 关联批次 → 返回结果
```

## 五、系统模块

### 1. 批次管理模块
- **功能**：创建、查询、更新批次信息
- **API**：`/api/batch/*`
- **数据模型**：`Batch` 表

### 2. 二维码管理模块
- **功能**：生成、查询、导出二维码
- **API**：`/api/code/*`
- **数据模型**：`TraceCode` 表

### 3. 任务管理模块
- **功能**：创建、执行、查询任务
- **API**：`/api/code/task/*`
- **数据模型**：`BatchTask` 表

### 4. 扫码记录模块
- **功能**：查询、分析扫码记录
- **API**：`/api/scan/*`
- **数据模型**：`ScanRecord` 表

### 5. 系统管理模块
- **功能**：系统配置、监控
- **API**：`/api/admin/*`

## 六、部署架构

### 1. 容器编排
使用 Docker Compose 编排三个容器：
- `trace_db`：PostgreSQL 数据库
- `trace_backend`：后端服务
- `trace_nginx`：Nginx 反向代理

### 2. 网络配置
- **内部网络**：三个容器通过内部网络通信
- **外部访问**：Nginx 容器暴露 80 端口，提供外部访问

### 3. 存储配置
- **数据卷**：使用 Docker 数据卷持久化数据库数据
- **挂载目录**：挂载日志目录和静态文件目录

## 七、系统扩展性

### 1. 水平扩展
- **后端服务**：可通过增加容器实例实现水平扩展
- **数据库**：可配置主从复制，提高数据库性能和可靠性

### 2. 垂直扩展
- **服务器配置**：可根据业务量增加服务器 CPU、内存等资源
- **容器资源**：可调整 Docker 容器的资源限制

### 3. 功能扩展
- **API 接口**：采用 RESTful API 设计，易于扩展新功能
- **模块设计**：采用模块化设计，便于添加新模块

## 八、系统安全性

### 1. 网络安全
- **防火墙**：配置服务器防火墙，限制外部访问
- **HTTPS**：生产环境建议配置 HTTPS
- **访问控制**：实现基于角色的访问控制

### 2. 数据安全
- **数据库备份**：定期备份数据库
- **数据加密**：敏感数据加密存储
- **审计日志**：记录系统操作日志

### 3. 代码安全
- **代码审计**：定期进行代码审计
- **依赖管理**：定期更新依赖包，修复安全漏洞
- **输入验证**：对所有用户输入进行验证，防止注入攻击

## 九、系统监控

### 1. 服务监控
- **Docker 监控**：使用 `docker stats` 监控容器资源使用情况
- **服务状态**：使用 `docker ps` 监控容器运行状态
- **健康检查**：配置容器健康检查

### 2. 日志监控
- **后端日志**：查看后端应用日志
- **Nginx 日志**：查看 Nginx 访问和错误日志
- **数据库日志**：查看数据库运行日志

### 3. 性能监控
- **响应时间**：监控 API 响应时间
- **数据库性能**：监控数据库查询性能
- **系统资源**：监控服务器 CPU、内存、磁盘使用情况

## 十、系统升级

### 1. 版本管理
- **代码版本**：使用 Git 进行代码版本管理
- **镜像版本**：使用 Docker 镜像标签管理版本

### 2. 升级流程
1. **备份数据**：执行数据库备份
2. **停止服务**：停止当前运行的服务
3. **更新代码**：更新代码和配置文件
4. **构建镜像**：重新构建 Docker 镜像
5. **启动服务**：启动更新后的服务
6. **验证功能**：验证系统功能是否正常

### 3. 回滚策略
- **备份恢复**：如果升级失败，使用备份恢复系统
- **版本回滚**：回滚到之前的 Docker 镜像版本

## 十一、架构优势

1. **容器化部署**：使用 Docker 容器化部署，简化部署和管理
2. **微服务架构**：模块化设计，便于扩展和维护
3. **高性能**：使用 FastAPI 框架，提供高性能的 API 服务
4. **可靠性**：数据库持久化，任务系统确保操作可靠执行
5. **安全性**：多层安全措施，保障系统和数据安全
6. **可扩展性**：支持水平和垂直扩展，适应业务增长

## 十二、架构演进

### 1. 当前架构
- **单节点部署**：所有服务部署在单个服务器上
- **简单队列**：使用内存队列处理任务

### 2. 未来架构
- **多节点部署**：服务部署在多个服务器上，实现高可用性
- **消息队列**：使用 Redis 或 RabbitMQ 作为消息队列，提高任务处理能力
- **负载均衡**：使用负载均衡器分发请求，提高系统性能
- **监控系统**：集成 Prometheus 和 Grafana，实现更全面的监控
- **CI/CD**：集成 CI/CD 流程，实现自动化部署
